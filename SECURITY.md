# Security Policy

## Supported Versions

| Version | Supported |
| --- | --- |
| 1.x | Yes |
| < 1.0 | No |

## Reporting A Vulnerability

Please avoid opening a public issue for security-sensitive reports.

Preferred reporting path:

1. Use GitHub security reporting or a private maintainer contact channel if it is available for this repository.
2. Include the affected version, steps to reproduce, required permissions, and any user data exposure risk.
3. Share proof-of-concept details privately until the issue is reviewed.

If no private reporting channel is available yet, contact the repository owner directly through the GitHub profile associated with this repository and include the word `security` in the subject or first line.

## Scope

Security reports are especially useful for issues involving:

- unexpected access to captured previews or stored tab metadata
- permission escalation through content scripts or background messaging
- data leakage through release packaging or browser storage handling
